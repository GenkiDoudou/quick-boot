# C7按钮（C7Button）原始需求

## 背景
- 页面中存在大量“新增/修改/删除/查询/重置”等常见操作按钮，期望统一样式、图标、交互（防抖、确认、loading、表单校验、提示）。

## 目标
- 在 `ElButton` 基础上提供“预设按钮类型 + 通用行为封装”。
- 默认支持：防抖、防重复点击、可选确认框、可选表单校验、异步执行 loading、成功/失败提示、事件回调。

## 功能需求
### 1. 预设按钮类型（btnType）
- 支持 `add/edit/delete/query/refresh/upload/download/submit/cancel` 等预设：
  - 自动配置 icon / label / type / plain。
- `label/type/plain/size` 等显式传入时应覆盖预设值。

### 2. 点击执行模型
- 点击流程（顺序固定）：
  1) 触发 `before-click` 事件
  2) 可选表单校验：`validate=true` 且传入 `validateRef` 时执行 `validateRef.validate()`
  3) 可选确认：`confirm=true` 时弹确认框或执行 `confirmFn`
  4) 执行业务函数：`clickFunction()`（支持 Promise）
  5) 成功判定：用 `checkSuccess(result)` 判断是否成功
  6) 成功/失败提示：`isSuccessCallback`/`showErrorToast` 控制提示
  7) 触发 `successCallback` 或 `errorCallback`，最后触发 `after-click(success)`

### 3. 防抖与 loading
- 点击处理必须支持防抖（`debounceDelay`，默认 300ms）。
- 执行 `clickFunction` 期间按钮进入 loading 状态。

## Props（关键）
- `btnType`：预设类型
- `clickFunction`：业务执行函数
- `debounceDelay`
- `confirm/confirmMessage/confirmFn`
- `validate/validateRef`
- `isSuccessCallback/successMessage/successNotify`
- `isErrorCallback/errorMessage/errorNotify/showErrorToast`
- `checkSuccess(result)`

## 事件
- `successCallback(result)`
- `errorCallback(error)`
- `before-click`
- `after-click(success:boolean)`

## 验收标准
- `btnType=delete + confirm=true` 时点击会先确认，再执行删除函数。
- `clickFunction` Promise 未完成前按钮显示 loading 且不会重复执行。
- `validate=true` 且校验失败时不进入确认/执行阶段。
