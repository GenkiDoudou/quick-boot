# quickboot2 项目优化分析

> **文档版本**：2026-05-22  
> **适用范围**：`quickboot/`、`quick-ui/`、`openspec/`、仓库协作与配置  
> **说明**：基于当前代码与配置静态审计，按优先级给出可落地项；不含对 `原始需求/RuoYi-Vue`、`bak/` 等参考目录的改造建议。

---

## 1. 摘要

项目已完成系统管理、监控（登录日志 / 操作日志 / 定时任务）、代码生成、防火墙与 Sa-Token 鉴权等主干能力，**common 层单测较充实**，但仍有若干**安全缺口**、**配置与规范不一致**、**异常处理重复**、**操作日志同步落库**、**OpenSpec 手工验收未完成**等问题。建议按 **P0 → P7** 分阶段推进，每阶段有可验证的完成标准。

| 优先级 | 主题 | 风险/收益 |
|--------|------|-----------|
| **P0** | 安全与生产配置 | 高：权限缺口、Actuator 匿名、生产 SQL/日志泄露 |
| **P1** | 异常与业务错误规范 | 中：重复 Advice、Cron 抛 `IllegalArgumentException` |
| **P2** | 操作日志 | 中：同步写库拖慢请求、元数据注解未推广 |
| **P3** | 代码生成 / 定时任务收尾 | 中：GET 写操作、树表、OpenSpec 验收 |
| **P4** | 前端性能与规范 | 中：Element Plus 全量、DESIGN token、Vitest 覆盖 |
| **P5** | 仓库与文档 | 低：H2 库入 Git、端口文档不一致 |
| **P6** | 模块与能力补齐 | 低：`quickboot-core` 空壳、监控子模块缺失 |
| **P7** | 中长期 | 规划：在线用户、服务监控、文件服务等 |

## 3. P0 — 安全与生产配置 ✅（已落地 2026-05-22）

### 3.1 Actuator / H2 匿名访问 ✅

- 默认（含生产）不再将 `/actuator/**`、`/h2-console/**` 写入 Sa-Token 固定放行列表。
- 开发环境通过 `qc.security.web.anonymous-paths`（见 `application-dev.yml`）按需放行。
- 生产 `management.endpoints.web.exposure` 仅 `health,metrics`，`health.show-details: never`。

### 3.2 接口权限注解 ✅

已为 `SysDeptController`、`SysMenuController`、`DictTypeController`、`DictDataController` 补齐 `@SaCheckPermission`（字典按类型查询为 `query|list` OR）。

### 3.3 生产 Profile 加固 ✅

`application-prod.yml` 已覆盖：MyBatis `Slf4jImpl`、`operlog.print: false`、`sa-token.is-log: false`、关闭 Druid 监控 Servlet/Filter。

### 3.4 开发环境 H2 Console

仍仅在 `application-dev.yml` 启用；生产无 H2 配置，且匿名路径为空。

## 4. P1 — 异常与错误码规范 ✅（已落地 2026-05-22）

### 4.1 `NotLoginException` 双重处理 ✅

已删除 `SaTokenExceptionAdvice`，统一由 `GlobalExceptionHandler#handleNotLogin` 映射 `ErrorCodes.Security.UNAUTHORIZED`。

### 4.2 `CronUtils` 使用 `IllegalArgumentException` ✅

`getNextExecution` / `getNextExecutions` 解析失败时改为 `WarningException(ErrorCodes.Job.CRON_INVALID, ...)`。

### 4.3 写操作 HTTP 方法 ✅

代码生成写操作已改为 POST：`/synchDb/{tableName}`、`/batchGenCode`（body）、`/genCode/{tableName}`；前端 `gen.js` 已同步。

---

## 5. P2 — 操作日志 ✅（已落地 2026-05-22）

### 5.1 异步落库 ✅

- 配置项 `qc.monitor.operlog.async-enabled`（默认 `true`）
- `OperLogAsyncPersistListener` + 专用线程池 `operLogTaskExecutor`
- `async-enabled=false` 时使用 `OperLogSyncPersistListener`

### 5.2 业务类型推断 ✅

- 新增 `OperLogBusinessType` 常量
- `OperLogMetaResolver.inferBusinessType` 按 POST 路径/方法名推断增删改导出导入
- 方法上 `@OperLogMeta(businessType=…)` 仍可显式覆盖

### 5.3 与控制台打印分工

- **落库**：业务审计，生产必开（capture-enabled）。
- **print**：仅 dev 调试；生产关闭（见 P0）。
