# 通用响应与分页模块（quickboot-common/common/core）原始需求

## 背景
- 后端接口需要统一返回结构，便于前端/网关/日志系统处理。
- 列表查询需要统一分页入参与分页返回结构，减少重复代码。
- 需要在响应中带上链路追踪信息，便于排障。

## 目标
- 提供统一响应对象 `R<T>`：`code/msg/data/traceId/timestamp`。
- 提供通用分页入参 `PageRequest<T>` 与分页出参 `PageInfo<T>`。
- 提供全局通用状态码常量。

## 功能需求
### 1. 统一响应 `R<T>`
- 字段：
  - `code`：业务码（默认成功 200）
  - `msg`：提示信息
  - `data`：业务数据
  - `traceId`：从 MDC/链路模块获取
  - `timestamp`：毫秒时间戳
- 工厂方法：
  - `ok()` / `ok(msg)` / `ok(data)` / `ok(msg,data)`
  - `error()` / `error(msg)` / `error(code,msg)` / `error(code,msg,data)`
- 判断方法：
  - `isSuccess()`：`code==200`
  - `isError()`：非 200

### 2. 分页请求 `PageRequest<T>`
- 字段：
  - `current`：页码（默认 1）
  - `size`：页大小（默认 10）
  - `param`：查询参数
- 提供 `getOffset()`：返回 `(current-1)*size`。

### 3. 分页返回 `PageInfo<T>`
- 字段：
  - `current/size/records/total/pages`
  - `ext`：扩展字段 Map（可选）
- `pages` 计算：`(total + size - 1) / size`。

### 4. 全局消息码
- 提供常用 HTTP 语义状态码常量：`200/400/401/403/404/500/503/...`

## 配置项
- 无（由调用方统一使用）。

## 依赖与边界
- 依赖：链路追踪模块（用于 `traceId`）。
- 边界：仅提供 DTO/常量，不包含业务错误码定义与异常映射逻辑（由异常模块承担）。

## 验收标准
- 任意接口返回均可封装为 `R<T>`，且 `timestamp` 非空。
- 在开启链路追踪/日志 MDC 时，`traceId` 能自动透传到响应中。
