# 缓存模块（quickboot-common/common/cache）原始需求

## 背景
- 业务接口存在高频读场景，需要引入缓存降低数据库/下游调用压力。
- 同一套代码需同时支持本地缓存（开发/单机）与分布式缓存（生产/集群）。
- 不同业务缓存项的过期时间不同，要求能“按缓存名动态指定 TTL”，避免为每个缓存单独写配置。

## 目标
- 支持 `Caffeine` 本地缓存与 `Redis` 分布式缓存两种模式。
- 支持通过 `cacheName#ttlSeconds` 的写法为**单个缓存**动态设置过期时间。
- 统一缓存序列化（Redis 场景）并避免缓存 `null` 值。

## 功能需求
### 1. 缓存类型切换
- 当 `spring.cache.type=caffeine` 时启用本地缓存管理器。
- 当 `spring.cache.type=redis` 时启用 Redis 缓存管理器（依赖 `RedisConnectionFactory/RedisTemplate`）。

### 2. 动态 TTL（按 cacheName）
- 约定缓存名支持 `cacheName#ttl`：
  - `cacheName`：实际缓存分区名。
  - `ttl`：过期秒数（整数）。
- 示例：`@Cacheable(cacheNames="userCache#3600", key="#id")` 表示缓存 3600 秒。
- 若 `ttl` 解析失败或未提供，则使用默认 TTL。

### 3. 默认策略
- 默认 TTL：3600 秒。
- Caffeine 默认最大条目数：10000。
- Redis：
  - Key 序列化：`StringRedisSerializer`
  - Value 序列化：`GenericJackson2JsonRedisSerializer`
  - 不缓存 `null` 值
  - 事务感知（transaction aware）

## 配置项
- `spring.cache.type`：`caffeine`（默认）/`redis`

## 依赖与边界
- 依赖：`spring-boot-starter-cache`、`caffeine`、`spring-boot-starter-data-redis`（Redis 模式）。
- 边界：仅提供 CacheManager 与动态 TTL 解析；具体业务缓存 key 设计由业务侧决定。

## 验收标准
- 在 Caffeine 模式下：
  - `cacheNames="a#1"` 缓存 1 秒后失效。
  - 未指定 `#ttl` 的缓存使用默认 3600 秒。
- 在 Redis 模式下：
  - 缓存 value 为 JSON 可读结构（而非 JDK 序列化）。
  - `null` 不入缓存。
  - `cacheNames="a#1"` 的 TTL 能生效（支持动态 TTL）。
