# 安全防火墙：安全头管理（firewall/headers）原始需求

## 背景
- 需要在所有 HTTP 响应中添加安全头，减少点击劫持、MIME 嗅探、部分 XSS 风险。
- 不同环境/场景需要可配置开关与可排除路径（如静态资源、特定回调接口）。

## 目标
- 提供可配置的安全响应头注入过滤器。
- 支持**两段式**按 URL 排除（完全跳过 vs 仅跳过强策略头），均支持 Ant 风格匹配。

## 功能需求
- 启用条件：`qc.security.firewall.headers.enabled=true`
- 对非排除请求，在响应提交前设置以下头（非空才设置）：
  - `X-Frame-Options`（默认 `SAMEORIGIN`）
  - `X-Content-Type-Options`（默认 `nosniff`）
  - `X-XSS-Protection`（默认 `1; mode=block`）
  - `Content-Security-Policy`（可选）
  - `Strict-Transport-Security`（可选）
  - `Referrer-Policy`（默认 `strict-origin-when-cross-origin`）
  - `Permissions-Policy`（可选）
- **路径排除（选型 D）**
  - **`excludeUrls`**：匹配的请求**不添加**本模块负责注入的上述**全部**头。
  - **`excludeFromStrictPolicyUrls`**：匹配的请求仍按「非空才设置」注入 **基础头**（`X-Frame-Options`、`X-Content-Type-Options`、`X-XSS-Protection`、`Referrer-Policy`）；**不设置**强策略头：`Content-Security-Policy`、`Strict-Transport-Security`、`Permissions-Policy`（即使配置项非空）。
  - **同时命中**两表时：以 **`excludeUrls`（完全跳过）为准**。

## 配置项
- 前缀：`qc.security.firewall.headers`
  - `enabled`（默认 `false`）
  - `frameOptions/contentTypeOptions/xssProtection/contentSecurityPolicy/strictTransportSecurity/referrerPolicy/permissionsPolicy`
  - `excludeUrls[]`（完全跳过上述全部头）
  - `excludeFromStrictPolicyUrls[]`（仅跳过 CSP / HSTS / Permissions-Policy）

## 验收标准
- 启用后，**未命中任一段排除**的任意接口响应包含按配置应出现的安全头。
- 命中 `excludeUrls` 的请求：响应中**不出现**本模块列出的任一上述头。
- 命中 `excludeFromStrictPolicyUrls`（且未命中 `excludeUrls`）的请求：出现基础头（若配置非空），**不出现** CSP、HSTS、Permissions-Policy。
