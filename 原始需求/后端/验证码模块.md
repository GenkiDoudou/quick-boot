# 验证码模块（quickboot-common/common/captcha）原始需求

## 背景
- 登录/关键操作需要防机器人、防暴力破解手段。
- 需支持行为验证码（滑块/旋转/点选等），并能在有 Redis 时走分布式存储，无 Redis 时走本地存储。

## 目标
- 提供统一的验证码生成与校验 API。
- 支持多种验证码类型配置切换。
- 支持验证码数据存储的 Redis/本地自适配。

## 功能需求
### 1. 对外接口
- 生成验证码：`GET/POST /api/captcha/generate`
  - 根据配置的类型生成验证码数据（返回 tianai 的 `ImageCaptchaVO`）。
- 校验验证码：`POST /api/captcha/validate`
  - 入参：`{ id: string, data: ImageCaptchaTrack }`
  - 校验通过返回 `success` 并回传 `id`（用于后续二次校验/登录绑定）。

### 2. 鉴权要求
- 验证码相关接口必须可匿名访问（登录前可用）。

### 3. 存储策略
- 当存在 `StringRedisTemplate` 时，验证码缓存使用 Redis 存储。
- 否则使用本地内存存储（进程内）。

### 4. 资源策略
- 内置一组背景图资源（classpath 下的 `bgimages/*`），支持滑块/旋转/点选等类型复用。

## 配置项
- 前缀：`qc.captcha`
  - `enabled`：是否启用（默认 `true`）
  - `type`：验证码类型（默认 `SLIDER`）
    - 可选：`SLIDER`、`ROTATE`、`CONCAT`、`WORD_IMAGE_CLICK`（以实际库支持为准）

## 依赖与边界
- 依赖：tianai captcha 相关 starter、（可选）Redis。
- 边界：
  - 模块提供“生成/校验”能力；登录业务如何绑定 captchaId、如何二次校验由业务模块决定。

## 验收标准
- `qc.captcha.enabled=true` 时：
  - `/api/captcha/generate` 可返回可用的验证码数据。
  - `/api/captcha/validate` 能对正确轨迹校验通过，对错误轨迹校验失败。
- Redis 存在时重启服务后（在有效期内）验证码校验仍可通过；无 Redis 时仅进程内有效。
