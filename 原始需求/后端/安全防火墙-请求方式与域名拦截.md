# 安全防火墙：请求方式与域名拦截（firewall/methodandhost）原始需求

## 背景
- 需要限制接口的允许访问方式（例如只允许 GET/POST）。
- 需要限制访问域名（Host 白名单）防止异常网关/回源等风险。

## 目标
- 在进入业务逻辑前拦截不允许的 HTTP Method 与 Host。
- 支持 URL 排除与通配符 Host 匹配。

## 功能需求
- 启用条件：`qc.security.firewall.method-and-host.enabled=true`
- 允许方法：`allowedMethods[]`
  - 为空则默认放行所有方法。
- 允许 Host：`allowedHosts[]`
  - 为空则默认放行所有 Host。
  - 支持：
    - 精确匹配：`example.com:8080`
    - 子域名通配符：`*.example.com`
    - 端口通配符：`localhost:*`
- `excludeUrls[]`：Ant 风格排除
- 拦截行为：
  - Method 不允许：返回 `ErrorCode.METHOD_NOT_ALLOWED (30401)`
  - Host 不允许：返回 `ErrorCode.HOST_NOT_ALLOWED (30402)`
  - 返回格式：统一 JSON（通过 `ServletUtils.writeResponse`）

## 配置项
- 前缀：`qc.security.firewall.method-and-host`
  - `enabled`
  - `allowedMethods[]`
  - `allowedHosts[]`
  - `excludeUrls[]`
  - `forbiddenMessage`

## 验收标准
- 配置仅允许 GET 后，POST 请求被拦截并返回对应错误码。
- Host 不在白名单时被拦截，白名单内请求放行。
