# 安全防火墙：敏感词过滤（firewall/sensitiveword）原始需求

## 背景
- 业务输入（评论/昵称/简介/工单等）需要过滤敏感词。
- 需要支持黑名单/白名单词库的配置与加载，并支持不同处理策略：
  - 替换（REPLACE）
  - 直接拒绝（THROW）
- 需要支持表单参数与 JSON 请求体的过滤。

## 目标
- 提供可配置启用的敏感词过滤器：
  - 对请求参数与 JSON body 做递归过滤/检测
  - 按策略替换或抛异常
- 支持忽略 URL 列表（如登录、验证码等不处理或自行处理）。

## 功能需求
### 1. 启用与忽略
- 启用条件：`qc.security.firewall.sensitive-word.enable=true`
- `ignoreUrls[]`：Ant 风格匹配，命中后跳过过滤。

### 2. 词库加载
- 支持文件路径列表：
  - `classpath:` 与 `file:` 前缀
  - 支持注释行（以 `#` 开头）与空行
- 黑名单：
  - 在内置默认词库基础上追加自定义黑名单
- 白名单：
  - 自定义白名单用于放行某些词（即使出现在黑名单/默认库中）

### 3. 过滤范围
- Query/Form 参数：
  - `getParameter/getParameterValues` 返回过滤后的结果
- JSON body：
  - 将 body 解析为 Map 后递归遍历：
    - String：过滤
    - Map：递归
    - 其他类型：原样保留
  - 重新序列化后下游读取到的是过滤后的 body

### 4. 处理策略
- `REPLACE`：将敏感词替换为 `*`（按库默认规则）
- `THROW`：检测到敏感词抛出 `SensitiveWordException`（错误码 `30501`，携带命中的敏感词）
- Filter 捕获异常后返回统一 JSON 错误响应。

## 配置项
- 前缀：`qc.security.firewall.sensitive-word`
  - `enable`
  - `whiteList[]`
  - `blackList[]`
  - `ignoreUrls[]`
  - `strategy`：`REPLACE|THROW`

## 依赖与边界
- 依赖：`sensitive-word` 三方库、Spring `ResourceLoader`、Jackson。
- 边界：只处理 HTTP 请求输入；数据入库后的二次校验/审核流程不在本模块范围。

## 验收标准
- 启用后包含敏感词的参数会被替换或直接拒绝（按 strategy）。
- JSON body 嵌套字段也能被正确处理。
- 命中 `ignoreUrls` 的接口不会被过滤。
