# 安全防火墙：密码加密（firewall/password）原始需求

## 背景
- 系统中存在多种“需要加密/校验”的场景：
  - 用户密码（推荐 bcrypt）
  - 客户端认证串（需要对称加密，如 SM4）
- 需要统一的编码器入口，支持按前缀标识不同算法，并提供匹配/升级能力。

## 目标
- 提供委托密码编码器 `DelegatingPasswordEncoder`：
  - 默认使用 bcrypt
  - 支持 SM4 加解密（用于客户端认证等）
  - 支持 `{id}ciphertext` 前缀格式
- 提供自动配置，业务可直接注入使用。

## 功能需求
### 1. 编码格式
- 加密输出格式：`{encoderId}<encoded>`
  - 例如：`{bcrypt}$2a$...`
  - 例如：`{sm4}a1b2c3...`

### 2. 算法支持
- `bcrypt`：
  - 加密：不可逆 hash
  - 校验：matches
  - 解密：不支持
- `sm4`：
  - 加密：需要提供 key（16 字节）
  - 解密：支持（用于服务端校验/解析）
  - key 以 properties 注入形式提供（例如 `setProperties({key: ...})`）

### 3. 委托能力
- `encrypt(rawPassword, encoderId)`：指定算法加密
- `matches(raw, prefixEncoded)`：
  - 若 prefix 存在且匹配到算法，使用对应算法校验
  - 若无 prefix，则使用默认算法校验
- `upgradeEncoding(prefixEncoded)`：用于密码策略升级（可选）

### 4. 自动配置
- 默认注册 `DelegatingPasswordEncoder` Bean（可被业务侧覆盖）。

## 配置项
- 无统一配置（SM4 key 通常由调用方按业务上下文传入）。

## 依赖与边界
- 依赖：Spring Security bcrypt、Hutool 国密工具（SM4）。
- 边界：本模块只提供算法能力，不负责密码策略（复杂度、历史校验、轮换等）。

## 验收标准
- bcrypt 加密后的密文可通过 `matches` 正确校验。
- sm4 在提供 key 后可加密/解密同一明文，且用于客户端认证串校验。
