# 链路追踪模块（quickboot-common）原始需求



## 背景

- 分布式/多模块场景排查问题需要 traceId 贯穿请求链路。

- 希望在日志与统一响应中都能带上 traceId，且可对接 OpenTelemetry/OTLP。



## 目标

- 提供工具类获取当前请求链路 `traceId`（从 MDC 获取）。

- 配合 Spring Boot 3 的 Micrometer Tracing 自动配置，实现 traceId 自动注入日志 MDC。

- 支持（可选）将链路数据导出到 OTLP endpoint。



## 功能需求

- **`TraceIds.current()`**：类 `io.github.genkidoudou.common.api.TraceIds`，从 `MDC["traceId"]`（与 `TraceIds.MDC_KEY` 一致）读取当前 traceId；值为空白时返回 `null`。**规范仅此一套读取入口**，不另设 `TraceUtil` 或 `common.trace` 包作为硬性要求。

- **Span 与传播**：由 **Spring Boot + Micrometer Tracing** 在服务端自动创建 span，或将请求接续到已有 trace。上游（浏览器、网关、其他服务）应通过 **W3C `traceparent`（及按需的 `tracestate`）** 等标准传播头传递上下文；本模块不在业务或 common 内手写创建 root span 以满足该行为。

- 与日志模块、统一响应模块协作：

  - `R` 在构造（`build`）时通过 `TraceIds.current()` 写入响应体 `traceId`。

  - 请求日志输出包含 traceId（与 `%X{traceId}` 同源）。

- 运维配置：

  - 可配置采样率

  - 可配置 OTLP endpoint



## 配置项（示例）

- `management.tracing.sampling.probability`

- `management.otlp.tracing.endpoint`

- 日志 pattern 中包含 `%X{traceId}`（或等价配置，且与 `TraceIds.MDC_KEY` 一致）



## 依赖与边界

- 依赖：SLF4J MDC、Micrometer Tracing / OpenTelemetry（由工程依赖与 Spring Boot 自动配置提供）。

- 边界：模块不直接创建 tracer/span，仅提供 traceId 读取与对接约定；异步线程若需同一 trace，须由调用方保证 MDC / 上下文传播（另述）。



## 验收标准

- 在启用 tracing 且该请求被采样的典型 Web 请求下，同一线程内日志与响应体中的 `traceId` 一致（或与「无 trace 上下文」一致地均为空，视采样与配置而定）。

- 配置 OTLP 后可在外部链路系统看到请求链路（可选验收项）。
