# Excel 工具迁移实施备注

## 1. 工具层与业务层职责边界
- `quickboot-common` 的 `io.github.genkidoudou.common.excel` 仅负责：读写 Excel、监听校验、错误聚合、字典转换与失败文件生成。
- 业务模块负责：唯一性判断、重复策略（IGNORE/OVERWRITE）选择、持久化写库、事务边界控制。
- 工具层不做批量入库策略，业务按模块自行控制逐条或批量写入。

## 2. 旧实现迁移路径
- 旧的模块内导入逻辑（例如 `DictExcelImportSupport`）逐步收敛到 `EasyExcelSupport + DefaultExcelListenerCallback + ExcelImportFieldException`。
- 旧逻辑保留一个迭代周期用于回滚，后续逐步删除重复实现。
- 新业务模块统一先在 `quickboot-common` 扩展能力，再在业务模块落地调用，避免再次复制监听器与错误模板。

## 3. 风险与回退
- 风险点：字段映射、字典转换、重复策略差异导致导入结果变化。
- 回退步骤：
  1. 保留旧导入入口开关（灰度可切换）。
  2. 出现批量失败时，切换回旧入口并导出失败明细复核。
  3. 对比新旧错误文件，确认字段映射与错误列输出一致后再全量切换。

## 4. 验证建议
- 覆盖空文件、空行、必填缺失、类型转换失败、重复数据（IGNORE/OVERWRITE）与字典翻译场景。
- 验证导入结果结构：总条数、成功条数、失败条数、失败行号、失败明细文件。
- 验证导出模板/导出数据在 Excel 客户端可正常打开且列头一致。
