## Context

当前仓库已具备部分 Excel 能力，但实现分散在 `quickboot-common` 与业务模块中，存在以下问题：
1. 导入处理路径不统一（全量读取/回调处理并存），异常与校验行为不一致。
2. 失败明细模型、错误列映射、失败文件生成逻辑在业务侧重复实现。
3. 导入策略语义（`IGNORE` / `OVERWRITE`）未形成统一模型，跨模块复用成本高。
4. 字典翻译、模板导出、合并策略虽有基础实现，但缺乏完整的工具层编排与接入规范。

约束条件：
1. 工具层不做批量写库，写库策略与重复语义由业务层定义。
2. 保持现有技术栈（Spring Boot 3 + EasyExcel + Jakarta Validation）。
3. 保持外部接口兼容，优先在字典模块验证后推广。

相关角色：
1. 平台开发：维护 `quickboot-common` 公共工具。
2. 业务开发：按统一接口接入导入导出能力。
3. 前端/测试：消费导入结果并验证失败明细行为。

## Goals / Non-Goals

**Goals:**
1. 在 `quickboot-common` 建立完整、可复用 Excel 工具体系（导入监听、校验、策略、失败明细、模板、导出、字典翻译、合并策略）。
2. 统一导入执行模板，减少业务重复代码，明确工具层/业务层边界。
3. 保留字段级错误能力，失败明细支持行号、列名（可中文化）、原因。
4. 统一导入策略模型，支持 `IGNORE` / `OVERWRITE` 并允许业务扩展。
5. 以字典模块完成首批接入，形成后续模块迁移范式。

**Non-Goals:**
1. 不在工具层实现数据库批处理（如 `ExecutorType.BATCH`），由业务模块自行决定。
2. 不一次性改造所有业务模块，仅完成公共能力与字典样板接入。
3. 不引入新的 Excel 框架或替换 EasyExcel。

## Decisions

1. **统一导入模板引擎（回调模式）**
- 决策：以 `DefaultExcelListenerCallback + importByCallback` 为标准导入路径。
- 理由：可实现逐行处理、错误聚合、字段级错误输出，且易于业务扩展。
- 备选：全量 `List` 后处理；不选原因是对错误定位与大文件处理不友好。

2. **Validation 与业务校验并行**
- 决策：导入行模型承载 Jakarta Validation；业务回调承载跨行/跨库规则。
- 理由：基础字段约束标准化，业务规则灵活扩展。
- 备选：全手写校验；不选原因是重复高且难统一。

3. **重复语义业务化**
- 决策：工具层仅提供错误承载，不定义重复规则；业务层判断是否重复。
- 理由：不同模块唯一键差异大，工具层硬编码会限制复用。
- 备选：工具层统一“重复即失败”；不选原因是破坏业务灵活性。

4. **失败明细标准化输出**
- 决策：统一 `ExcelImportErrorRow` 与失败文件生成逻辑，业务只提供字段映射。
- 理由：确保前端消费体验一致，减少重复拼装。
- 备选：业务自行输出失败文件；不选原因是格式碎片化。

5. **导出能力统一编排**
- 决策：保留并强化 `EasyExcelSupport`，统一普通导出、模板导出、字典翻译导出、合并导出入口。
- 理由：降低模块接入门槛，避免重复工具方法。
- 备选：各模块自管导出；不选原因是维护成本高。

## Risks / Trade-offs

- [风险] 导入回调中频繁数据库查询导致性能波动  
  → 缓解：业务层可做预查询缓存（如批量加载已存在 key），并控制单次导入行数。

- [风险] 失败文件过大导致响应体膨胀（Base64）  
  → 缓解：设置失败明细上限，超过阈值时改为落地文件并返回下载地址。

- [风险] 旧导入逻辑与新工具并存导致行为不一致  
  → 缓解：制定迁移清单，样板模块通过后按统一模板迁移。

- [风险] 列名映射遗漏导致“未知列”过多  
  → 缓解：在业务接入模板中强制提供 `columnLabelMapper` 并加测试断言。

## Migration Plan

1. 在 `quickboot-common` 完成 Excel 工具层能力补全与 API 定稿。
2. 以字典模块（type/data）接入新导入模板，保持接口返回兼容。
3. 增加 common 单测与字典模块集成测试。
4. 标注旧实现为待迁移路径，新增模块必须接入新模板。
5. 分批迁移其它业务模块，完成后清理重复实现。

回滚策略：
1. 保留旧导入路径与原接口开关。
2. 新接入模块出现问题时可切回旧路径。
3. 工具层变更采用小步提交，支持按 commit 回退。

## Open Questions

1. 失败明细文件传输是否长期使用 Base64，还是统一改为对象存储地址返回？
2. 导入文件行数上限与失败明细上限的默认阈值是否需要平台级配置化？
3. 是否需要为高并发导入场景增加异步任务模式（提交任务 + 查询进度）？
