# 后端代码规范（单文件总册）

本文档为 **quickboot** 后端在**当前仓库**内的合并版规范，依据 `quickboot/` 下 Maven 多模块源码、`pom.xml`、配置文件与既有实现归纳；**未在代码中出现的约定不虚构**。与 `AGENTS.md`、OpenSpec（如 `common-response-paging`）冲突时以**仓库源码与本文可追溯依据**为准。

---

## 概述与使用说明

- **适用范围**：`quickboot/` 目录下的 Java 后端（Spring Boot 3 + MyBatis-Plus）。
- **使用方式**：新增 Controller / Service / Mapper / 实体与横切能力时，对照各章保持包结构、响应契约、持久化与公共组件用法一致。
- **单文件维护**：规范集中在本文件；修改通用能力（`quickboot-common`）时须同步核对本章「公共工具 / 公共技术组件」是否与实现一致。

## 后端项目结构

依据目录与 `pom.xml` 模块声明：

```
quickboot/                          # Maven 父工程（artifactId: quickboot）
├── pom.xml                         # 版本与 dependencyManagement
├── quickboot-common/               # 通用库（工具、统一 API、安全防火墙、文件存储等）
│   └── src/main/java/io/github/genkidoudou/common/...
│   └── src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
├── quickboot-core/                 # 核心扩展模块（当前无 Java 源码，仅占位资源）
└── quickboot-web/                  # 可执行 Web 应用
    └── src/main/java/io/github/genkidoudou/
    │       WebApplication.java       # 启动类
    │       web/auth/...            # 认证相关 MVC 配置与控制器
    │       web/system/...          # 业务分包示例（如 system/dept）
    └── src/main/resources/
            application*.yml
            logback-spring.xml
            db/migration/           # Flyway 脚本
```

**根包**：`io.github.genkidoudou`（启动类）与 `io.github.genkidoudou.web`（Web 业务分包）。

## 分层结构

**目标形态**（与 `AGENTS.md` 及现有 `web/system/dept` 一致）：

| 层次 | 建议包路径（web 模块内） | 说明 |
|------|-------------------------|------|
| Controller | `...web.<域>.<子域>.controller` 或按域扁平化（现有 `web.auth` 为认证） | 仅编排与入参校验，返回 `R<?>` |
| Service | `...service` / `...service.impl` | 事务与领域规则；当前仓库中部分域仅有持久层占位 |
| Mapper | `...mapper` | MyBatis-Plus `BaseMapper` + `@Mapper` |
| 实体 / 表映射 | `...domain` 或与团队约定的 `entity` | 与表名、`@TableName` 对齐 |

**依赖方向**：Controller → Service → Mapper；实体可被 Service 与 Mapper 共用。`quickboot-common` 不依赖 `quickboot-web`。

---

## Controller层规范

- **基类**：无强制基类；使用 `@RestController` 声明 REST 控制器（见 `AuthController`）。
- **返回类型**：对外 JSON 统一为 `io.github.genkidoudou.common.api.R<T>`；成功 `R.ok(...)`，失败 `R.error(HttpCodes.xxx, "说明")`。
- **HTTP 状态码**：与 `HttpCodes` 文档一致——**业务成败看 JSON 的 `code` 字段**；多处 Advice 仍返回 HTTP 200 + `R`（如 `SaTokenExceptionAdvice`）。
- **分页入参**：使用 `PageRequest<T>`（`current`/`size`/`param`），配合 Bean Validation（`@Min(1)`）在需要时校验。
- **认证**：除 `SaTokenWebMvcConfig` 中 `excludePathPatterns` 外，默认需登录；业务方法可显式 `StpUtil.checkLogin()`（见 `AuthController#getInfo`）。

---

## Service层规范

- **约定**：业务规则、事务边界（`@Transactional`）放在 Service；Controller 不做复杂业务。
- **现状**：`quickboot-web` 中已有 `AuthController` 内联占位逻辑与 `SysDeptMapper` + `SysDept` 实体；**完整 Service 实现可按域逐步补全**，新建时建议 `XxxService` / `XxxServiceImpl` 命名，与 Mapper、实体同域分包。

---

## 数据访问层规范

- **Mapper 接口**：置于 `...mapper` 包；继承 `com.baomidou.mybatisplus.core.mapper.BaseMapper<Entity>`；标注 `@Mapper`（见 `SysDeptMapper`）。
- **XML**：`application.yml` 中 `mybatis-plus.mapper-locations: classpath*:mapper/**/*.xml`；无 XML 时仅注解 SQL 亦可。
- **全局策略**：见「持久层操作」章 MyBatis-Plus 配置（逻辑删除、主键策略、字段填充等）。

## 数据传输

| 类型 | 命名与用途 | 依据 |
|------|------------|------|
| 表实体 | 与表对应，如 `SysDept`；使用 `@TableName`、`@TableId`、`@TableLogic`、`@TableField(fill=...)` | `web/system/dept/domain/SysDept.java` |
| DTO / VO / Query | 仓库内**尚未**形成统一后缀样例；建议入参对象后缀 `Request`/`Query`，出参展示层后缀 `Vo`，与实体字段映射在 Service 层完成 | **规划建议**（待首个用例落地后固化） |
| 统一响应 | 直接使用 `R<T>` 承载业务数据，非再包一层 | `R.java` |

## 异常处理

- **框架级**：`SaTokenExceptionAdvice` 捕获 `NotLoginException` → `R.error(HttpCodes.UNAUTHORIZED, ...)`。
- **幂等**：`IdempotentExceptionHandler` 捕获 `IdempotentException` → HTTP 200 + `R.error(业务码, ...)`（与 `HttpCodes.IDEMPOTENT_REPEAT` 对齐）。
- **Filter 层错误**：未进入 Controller 时可用 `ServletUtils.writeResponse` 写出 **HTTP 200** + `R` 形态 JSON；须在 `LocaleContextHolder` 已设置 Locale 之后调用（见 `ServletUtils` JavaDoc 与 `AGENTS.md`）。
- **全局业务异常到 R 的完整映射**：若后续引入统一 `@RestControllerAdvice` 处理业务异常，应与本章并列维护；**当前仓库以分散 Advice + 防火墙异常为主**。

## 日志记录

- **实现**：Logback（`quickboot-web/src/main/resources/logback-spring.xml`）。
- **Pattern**：控制台与文件均包含 `traceId=%X{traceId}`、`spanId=%X{spanId}`，与 Micrometer/MDC 联动。
- **文件**：按 `logging.file.path`（默认 `./logs`）滚动；INFO / ERROR 分文件；大小与保留天数由 `logging.max-*` 等 Spring 属性注入。
- **根级别**：`INFO`。
- **与统一响应**：`R` 中 `traceId` 通过 `TraceIds.current()` 读取 MDC，与上述 pattern 键名一致。

## 注释规范

- **已有代码风格**：公开 API（如 `R`、`PageRequest`、`I18nUtil`、`TraceIds`、Controller 方法）使用 **JavaDoc**（`/** ... */`），说明职责、参数、返回值、前置条件与边界（见 `AuthController`、`SysDept`）。
- **协作要求**：新建 **public** 类型及其 **public/protected** 成员应具备可维护 JavaDoc；非显而易见的分支、事务、与外部系统约定需简短说明（与仓库 `AGENTS.md` 中「生成代码注释要求」一致）。

## 常量类命名规范

- **业务 HTTP 语义码**：集中放在 `final class HttpCodes`（私有构造器），字段为 `public static final int`（见 `HttpCodes.java`）。
- **其他常量**：建议 `XxxConstants` 或按域枚举；避免魔法数散落在 Controller/Service。

## 持久层操作

依据 `application.yml` 中 `mybatis-plus` 节点：

- **主键**：全局 `id-type: assign_id`；实体可用 `@TableId(type = IdType.ASSIGN_ID)` 显式声明。
- **逻辑删除**：`logic-delete-field: del_flag`；删除值 `1` / 未删除 `0`；实体用 `@TableLogic`。
- **字段策略**：`insert-strategy: not_empty`，`update-strategy: not_null`，`where-strategy: not_empty`。
- **下划线转驼峰**：`map-underscore-to-camel-case: true`。
- **审计字段**：实体示例使用 `@TableField(fill = FieldFill.INSERT)` / `INSERT_UPDATE`（与全局填充处理器配合；填充器以实际注册类为准）。
- **SQL 日志**：当前配置 `log-impl: org.apache.ibatis.logging.stdout.StdOutImpl`（开发友好；生产环境建议改为 slf4j 或关闭）。

**Flyway**：脚本位于 `quickboot-web/src/main/resources/db/migration/`，命名遵循 `V{version}__description.sql`。

## 分页操作

- **入参**：`io.github.genkidoudou.common.api.PageRequest<T>` — `current` 默认 1，`size` 默认 10，均 `@Min(1)`（见类注释与单元测试 `PageRequestPageInfoTest`）。
- **出参**：`io.github.genkidoudou.common.api.PageInfo<T>` — 通过 `PageInfo.from(IPage<T>)` 由 MyBatis-Plus 分页结果转换；支持 `from(page, ext)` 附加扩展 Map。
- **Service 内**：将 `PageRequest` 转为 `com.baomidou.mybatisplus.extension.plugins.pagination.Page` 执行查询，再 `PageInfo.from` 返回。

## 统一响应与核心对象

| 类型 | 说明 |
|------|------|
| `R<T>` | 字段：`code`、`msg`、`data`、`traceId`、`timestamp`；成功码 `HttpCodes.OK`（200）；`isSuccess()` 当且仅当 `code == 200` |
| `HttpCodes` | 与 HTTP 语义对齐的**业务响应码**（含防火墙、幂等等业务码段） |
| `TraceIds` | `TraceIds.current()` 从 MDC 读取 `traceId` |
| `PageRequest` / `PageInfo` | 分页入参与出参契约 |

**约定**：对外 API **HTTP 状态码保持 200**（错误场景亦常见），由客户端根据 JSON `code` 判断（见 `HttpCodes` 类注释与 `AGENTS.md`）。

## 公共工具

以下均位于 `quickboot-common` 的 `io.github.genkidoudou.common` 下，**以源码为准**。

| 工具 / 类型 | 职责摘要 |
|-------------|-----------|
| `I18nUtil` | 基于 `MessageSource` + `LocaleContextHolder` 取词条；须在容器就绪后调用 |
| `ServletUtils` | Filter 等场景写出 JSON 形态 `R`；固定 200 + UTF-8 |
| `TraceIds` | 从 MDC 取 traceId，供日志与 `R` 对齐 |
| `CacheNameTtl`（record） | 解析 `@Cacheable(cacheNames)` 中分区名与 TTL |

### `I18nUtil` 使用要点

- 通过 Hutool `SpringUtil` 获取 `MessageSource`；无容器时行为见源码。
- **不**负责完整 Web 语言切换链路；切换依赖 `LocaleResolver` 等与 `LocaleContextHolder` 的配合。

### `ServletUtils.writeResponse` 禁止误用

- 调用前须保证 **Locale 已写入 `LocaleContextHolder`**，否则国际化文案可能非预期。
- `response.isCommitted()` 时直接返回，不再写入。

## Controller 生成约束（补充）

- 生成或脚手架产出的写操作接口默认不使用 `@PutMapping`、`@DeleteMapping`，统一采用 `@PostMapping`（例如 `/update`、`/remove/{id}`）表达修改/删除动作。
- Controller 入参必须启用 Jakarta Validation：类级建议 `@Validated`，请求体使用 `@Valid`，字段/参数使用 `@NotNull`、`@Min`、`@Pattern` 等注解。
- 接口必须补齐 OpenAPI 注解，至少包括：类级 `@Tag`、方法级 `@Operation`、关键参数 `@Parameter`。
- 业务失败不得通过 `IllegalArgumentException` 向上抛出；统一抛项目自定义异常（如 `BaseException`/`WarningException`）并由全局异常处理映射为 `R.error(...)`。
