## 工程目录结构

以下内容以 **单仓单前端根**（推荐 `web/`）示意，**非当前仓库既有结构**（基于用户澄清，待项目落地后核对）。

```text
web/
├── public/                 # 静态资源，不经过打包变换策略外的处理
├── src/
│   ├── api/               # 按业务域划分的接口方法（薄层，调用 request）
│   ├── assets/            # 图片、字体等需打包资源
│   ├── components/        # 通用业务组件（跨多页复用）
│   ├── composables/       # 组合式函数（可测、无 DOM 副作用优先）
│   ├── constants/        # 前端常量、与字典 key 映射（非后端全量字典）
│   ├── layouts/          # 布局壳（带侧边栏/顶栏等）
│   ├── router/           # 路由定义与守卫
│   ├── stores/           # Pinia stores
│   ├── styles/           # 全局 SCSS、变量、mixin
│   ├── utils/            # 纯工具函数、request 封装
│   ├── views/            # 页面级视图（与路由一对一或可嵌套）
│   ├── App.vue
│   └── main.ts
├── index.html
├── vite.config.ts
├── tsconfig.json
└── package.json
```

**职责说明**：

- `api`：只放「请求函数」，不写 UI 逻辑；命名与后端模块对应。
- `views`：页面入口，可组合 `components`；复杂列表/表单可再拆子组件。
- `components`：多处复用的块，需有明确 props/emit 契约。
- `router`：路由元信息（标题、权限、缓存等）集中声明，避免散落魔法字符串。

## 文件命名规范

- **Vue 单文件组件**：业务通用组件用 **PascalCase**，如 `UserSelect.vue`；页面若单文件也用 PascalCase 或与路由名一致（团队选定一种后不变）。
- **TS/JS 模块**：工具与 API 使用 **camelCase** 文件名（如 `formatDate.ts`、`userApi.ts`）；类型定义可与实现同名或 `types.ts` 同目录共存。
- **样式**：全局 `styles/` 内可用 **`_` 前缀** 表示 partial（如 `_variables.scss`），依团队惯例；组件内优先 `<style scoped lang="scss">`。
- **路由 path**：kebab-case 路径段（如 `/user-center/profile`）与业务可读性平衡，**同一项目内统一**。
- **Pinia store**：`useXxxStore`，文件 `xxx.ts` 或 `xxxStore.ts`，全仓统一一种。

---

## 文件存放规范

- **页面**：放在 `views/`，可按业务分子目录，如 `views/user/List.vue`。
- **仅单页使用的组件**：可放在该 `views/` 子目录下的 `components/`，避免污染全局 `src/components`。
- **API**：`api/` 下按 **后端模块或领域** 分文件，禁止单文件堆砌全站接口。
- **静态资源**：小图标、组件强相关图放各组件旁或 `assets` 子目录；公共大图放 `assets/images`。
- **环境变量**：仅使用 Vite 约定前缀（如 `VITE_`），禁止把密钥写入前端；**`.env.*` 不进版本库若含敏感信息**（按公司规范）。

---

## 接口调用规范

- **封装**：在 `src/utils/request.ts`（或同等路径）创建 Axios 实例，统一设置 `baseURL`（来自 `import.meta.env.VITE_API_BASE_URL`）、超时、`withCredentials` 等。
- **拦截器**：
  - **请求**：附加鉴权头（Token）、traceId、统一 Content-Type。
  - **响应**：统一解析业务 code；**业务失败**与 **HTTP 错误**分层处理；401/403 与登出、跳转登录页策略写在一处。
- **api 层**：每个接口导出 **具名函数**，返回类型与后端约定对齐（DTO/interface 放 `api` 旁或 `types`）。
- **错误提示**：Element Plus `ElMessage` / `ElNotification` 在拦截器或业务层 **一处为主**，避免重复弹窗。
- **依据**：根据用户澄清选用 Axios；具体 baseURL 与环境文件待项目初始化后写入。

## 公共样式规范

- **入口**：在 `main.ts` 引入 `styles/index.scss`（或同等），其中 **先变量后全局重置**。
- **变量**：颜色、字号、间距、圆角、z-index 等放在 `styles/_variables.scss`，**禁止魔法数字散落**；与 Element Plus 主题 Token 对齐时单独文档记录。
- **组件样式**：默认 `scoped`；需穿透时使用 `:deep()`，并注明原因。
- **BEM**：可选；若采用，在 `components` 大组件上统一，不在全仓混用多种方法论。

## 公共函数调用方法

- **工具函数**：统一从 `utils/` 引入，**禁止**在业务文件内复制粘贴相同逻辑。
- **组合式函数**：与 Vue 生命周期、响应式相关的放入 `composables/`，命名 `useXxx`；纯逻辑可优先 `utils`。
- **日期/金额/脱敏**：若有通用实现，集中在 `utils/format` 等模块，并在本表或代码注释中说明使用场景。
- **请求**：业务代码 **只调用** `api/` 中函数，不直接各处 `request.get/post`。

**依据**：根据用户澄清的目录约定；具体函数清单待代码产生后维护（可在 `utils/index` 或文档小节补充）。

## 字典使用规范

- **目标**：与后端字典/枚举联动，保证表格列、表单选项与编码一致（基于用户澄清）。
- **约定**：
  - 字典数据通过 **专用接口** 拉取；Pinia 或独立 `composables/useDictionary` 做 **按类型缓存**，避免同页重复请求。
  - 前端保留 **`constants/dictKeys.ts`（或同等）** 存放字典类型编码常量，**禁止**魔法字符串。
  - 展示层：表格列 formatter、表单 `el-select` 选项统一走 **「code → label」** 映射函数。
  - 提交前：表单值一般为 **code**，与后端契约一致；若后端接受 label，须在接口文档中明示（不推荐）。
- **首版未定时**：接口与缓存策略待后端定型后，在本节追加「接口路径、刷新策略、离线兜底」条款。

**依据**：根据用户澄清；实现细节待接口与首版页面落地后核对。
