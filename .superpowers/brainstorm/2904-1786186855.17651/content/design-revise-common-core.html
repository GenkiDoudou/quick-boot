设计修订：保留 common + core

回应：不合并为 platform；common=工具模块；core=项目间共享

变更点

取消「common + core → platform（薄化）」。第一阶段 Maven 底座保持两层共享，再叠加业务模块与 app。

修订后逻辑视图
quickboot-app — 启动 / 组装 / Modulith 校验
↓
quickboot-module-system — Modulith 业务模块（api / internal）
↓
quickboot-core — 项目间共享（BaseEntity、项目级约定/抽象）
可被本仓库业务模块及其他项目复用；禁止依赖任何 module-*
↓
quickboot-common — 独立工具模块（无业务：异常、校验、Excel、缓存封装等）
最底层；不依赖 core / module / app

这样更好的地方

  • 契合「工具」与「项目共享」两种复用粒度
  • 其他项目可只引 common，或 common+core
  • 迁移成本更低（少一次大改名）

仍要守住的边界

  • common / core 都不放业务表实体与业务 Service
  • core → common 单向；禁止反向
  • 业务域只通过他域 api 协作，规则不变

依赖假设（若不对请改）

app → module-* → core → common。Modulith 应用模块仍从业务域算起；common/core 作为共享内核，一般不标成业务 Application Module。
