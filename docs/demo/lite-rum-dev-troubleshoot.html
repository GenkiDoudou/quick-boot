静态 Mock · 面向开发排障 · 不含统计大盘 op={{ q.operationId }} trace={{ q.traceId }}
开发日常不是看大盘，而是接 bug / 线上反馈时要快速回答这几句：
  1. 报错堆栈是什么？是不是同一个问题？（指纹）
  2. 用户当时在哪个页、从哪来、点了什么、调了哪些接口？
  3. 后端同一次请求日志 / 慢 SQL 在哪？（traceId）
  4. 是不是只有某浏览器 / 某 IP 网段才出？（UA、IP）

PV/UV、健康分、成功率大盘、地区/运营商饼图、告警运营台——那些是运维/产品看趋势的； 开发排障优先要可检索的个案：错误、操作、trace、环境。

对开发的作用：拿到和本地类似的 stack，用 fingerprint 判断是否同一类问题； 再顺着 operationId / traceId 去追现场，而不是只看「错误率涨了」。
对开发的作用：复现「用户路径」—— fromPage → page → action → api → error。 比「某个接口失败了」多一层：知道是哪个按钮串起来的。
