## 2. 目标与非目标

**目标**

- 列表：搜索能力更接近 PC 常用条件；卡片字段用 `QbJsonCardFields`（或同等 JSON）展示更全的关键信息
- 表单：补齐主业务字段；提交前做必填 / 格式校验
- 体验与视觉：沿用现有 H5 CRUD 壳（`QbSearchBar` / `QbListCard` / `qb-kv`），不搬 PC 表格交互

**非目标**

- 导入导出、Excel、批量勾选删除全量
- 菜单管理 / RUM / LogHub 等 H5 未落地模块
- 定时任务 Cron 编辑（仍仅启停 / 执行）
- 完整移动端 C7JsonTable / QbJsonForm

## 3. 统一约定

### 3.1 搜索

扩展现有搜索条模式（优先小改 `QbSearchBar` 或页内加一行筛选）：

| 模式 | 说明 |
|------|------|
| 关键词 | 主输入，映射 PC 最常用 text 条件（如 userName / roleName） |
| 筛选芯片 | 状态等枚举用 `QbStatusChips` 或横向选项；选中后重置分页刷新 |
| 第二关键词 | 仅当 PC 强依赖第二文本条件时增加（如参数键名）；否则合并进 placeholder 提示 |

`usePagedList` 扩展（或页面自管）：`filters` 对象并入 fetcher 的 `param` / query。

### 3.2 列表字段

- 有表单 CRUD 的模块：meta 优先 `QbJsonCardFields` + `cardColumns`
- 只读日志类：同样用 columns 配字段；详情页补关键长文本
- 状态继续放 `#status` 槽（`QbDictTag`），不塞进 columns（与用户页样板一致）

### 3.3 表单与校验

新增 `quick-h5/src/utils/validate.ts`（示例能力）：

- `required(label, value)`
- `mobile(value)`（可空则跳过）
- `email(value)`（可空则跳过）
- `assert(conditions)` → 失败 `toastInfo` 并中断提交

各表单 `onSubmit` 先跑校验再请求；不引入重型 schema 库。

### 3.4 实现策略（一次改完）

按模块批量改 API 类型（如需）→ 列表 index → form/detail；最后统一冒烟清单。

## 4. 分模块字段矩阵（实用对齐）

### 4.1 系统 — 用户

| 区域 | H5 目标（相对现状） |
|------|---------------------|
| 搜索 | 账号关键词 + 状态筛选（部门筛选可选二期；一期不做树选） |
| 列表 | 已有部门/角色/手机/邮箱；补性别（dict）、可选备注摘要 |
| 表单 | 补 email、sex、remark；保留部门/角色；校验：账号昵称必填、部门角色必选、手机/邮箱格式 |
| 备注 | 编辑须继续回传 `deptId`/`roleIds` |

### 4.2 系统 — 角色

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 角色名称关键词 + 状态 |
| 列表 | `QbJsonCardFields`：权限字符、排序、备注（可选） |
| 表单 | 现有字段保留；校验：名称、权限字符必填 |

### 4.3 系统 — 部门

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 部门名称 + 状态（若接口支持） |
| 列表 | 补负责人、电话（有则显示） |
| 表单 | 校验：部门名称必填；上级部门必选（含根） |

### 4.4 系统 — 参数

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 名称关键词 + 系统内置（是/否）筛选 |
| 列表 | columns：键名、键值、备注 |
| 表单 | 校验：名称/键名/键值必填；内置参数键名只读规则保持 |

### 4.5 系统 — 字典类型 / 数据

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 类型：名称关键词 + 状态；数据：标签关键词 |
| 列表 | 类型补备注；数据补排序展示（已有则强化 columns） |
| 表单 | 类型：名称/类型必填；数据：标签/键值必填 |

### 4.6 系统 — OAuth 客户端

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 名称关键词 + 状态 |
| 列表 | 补 apiPath 摘要、token 超时、是否验证码 |
| 表单 | 校验：clientId/名称/apiPath 必填；secret 掩码逻辑保持 |

### 4.7 系统 — 文件分类 / 文件

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 分类：名称；文件：文件名（可加分类筛选若选项易得） |
| 列表 | 分类：后缀/大小上限；文件：分类、大小、上传人 |
| 表单 | 分类：键+名称必填；文件上传仍必选分类 |

### 4.8 监控 — 定时任务 / 调度日志

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 任务：名称 + 状态；日志：任务名（已有 query）+ 状态 |
| 列表 | 任务补组名、Cron、调用目标摘要；日志补耗时/消息 |
| 表单 | 任务仍无 Cron 编辑 |

### 4.9 监控 — 登录 / 操作日志

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 登录：用户名 + 状态；操作：模块标题关键词 + 状态 |
| 列表 | 登录补地点/浏览器；操作补耗时/方法 |
| 详情 | 操作日志长字段保持可折叠 |

### 4.10 监控 — 在线用户 / 慢 SQL

| 区域 | H5 目标 |
|------|---------|
| 搜索 | 在线：用户名；慢 SQL：URI 关键词（可加来源筛选若字典简单） |
| 列表 | 在线补部门/IP/登录时间；慢 SQL 补耗时/类型/操作人 |
| 详情 | 慢 SQL 全文保持 |

## 5. 共享改造清单

| 项 | 内容 |
|----|------|
| `utils/validate.ts` | 必填与手机/邮箱等 |
| `QbSearchBar` 或页级筛选条 | 支持状态芯片 / 次要筛选（尽量少改 API：可选 `filters` slot） |
| `usePagedList` | 支持额外 filter 参数（最小扩展） |
| 各 `index.vue` / `form.vue` / `detail.vue` | 按 §4 落地 |
| API 类型 | 补 email/sex/remark 等展示字段（若类型缺失） |

## 6. 验收标准

1. 每个业务列表至少具备：关键词搜索 +（适用时）状态类筛选  
2. 卡片字段相对现状信息更全，且多用 `cardColumns` 配置  
3. 有写表单的模块：必填项与手机/邮箱格式有客户端校验文案  
4. 权限按钮、超管/内置禁操作规则不回归  
5. 无导入导出、无任务 Cron 编辑  

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 一次改面过大 | 按目录分批提交本地自测；冒烟 checklist 按模块勾 |
| 后端 param 不支持某筛选 | 以现网 API 为准，不做的筛选在设计矩阵中降级为「仅关键词」 |
| 列表字段过多挤爆卡片 | 长字段 stack + showIfProp；次要字段可省略 |

## 8. 推荐实现顺序（仍一次交付）

1. 共享：`validate` + `usePagedList` filters + 搜索条扩展  
2. 系统：用户 → 角色 → 部门 → 参数 → 字典 → 客户端 → 文件分类/文件  
3. 监控：job/jobLog → logininfor/operlog → online/slowSql  
4. 全量冒烟
