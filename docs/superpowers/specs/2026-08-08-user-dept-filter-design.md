# 用户管理按部门筛选（含下级）设计

日期：2026-08-08  
状态：已定稿（待实现）

## 1. 背景与目标

现状：

- `system/user` 与 `system/dept` 为独立页面；用户表单已可选择归属部门，列表展示 `deptName`。
- 用户分页/导出在传入 `deptId` 时仅做**精确匹配**（`eq`）。
- 用户页搜索区尚无部门条件。

目标：

- 用户可在**独立部门管理页**维护部门（本需求不改该页）。
- 用户管理页搜索区可按归属部门筛选，且选中部门时包含**本部门及全部下级**用户。

非目标：

- 不做左树右表布局，不合并/取消独立部门菜单。
- 不新增 `ancestors` 列，不做数据权限改造。
- 不新增 API 路径或权限码。

## 2. 决策摘要

| 议题 | 选择 |
|------|------|
| 交互形态 | 仅在用户页搜索区加部门树选（方案 C） |
| 筛选范围 | 本部门 + 全部子孙（方案 B） |
| 实现路径 | 后端展开子部门 ID 后 `IN`；前端搜索 slot + `el-tree-select`（方案 1） |
| 导出 | 与分页共用同一套部门 ID 解析，范围一致 |

## 3. 前端

**文件**：`quick-ui/src/views/system/user/index.vue`

- `searchColumns` 增加 `deptId`，`type: 'slot'`，标签「归属部门」。
- 使用 `C7JsonTable` 已有搜索 slot，挂载 `el-tree-select`：
  - 数据：现有 `treeselectDept()` → `deptTree`（与表单共用）
  - `check-strictly`、`clearable`、`value-key=deptId`
  - 绑定 slot 的 `form-data.deptId`
- `defaultSearch` 增加 `deptId: undefined`（或等价空值），重置时清空部门条件。
- 未选部门：不传有效 `deptId`，行为与现网一致。
- 用户表单归属部门逻辑不变；不改 `C7JsonTable` 公共组件、不改部门管理页。

## 4. 后端

**文件**：`SysUserServiceImpl`（已注入 `SysDeptMapper`）

当 `page` / `listForExport` 的查询参数 `deptId != null` 时：

1. 查询全部部门（至少 `deptId`、`parentId`）。
2. 内存构建父子关系，从选中节点收集自身及全部子孙 ID。
3. `dept_id IN (...)`，替代当前 `eq`。

抽私有方法（如 `resolveDeptIdsIncludingChildren(Long deptId)`），分页与导出共用。

边界：

- `deptId == null`：不加部门条件。
- 叶子部门：`IN` 仅含自身，结果等价于原 `eq`。
- 部门 ID 不存在：`IN (该 id)`，结果为空即可，不额外报错。
- 停用子部门 ID 仍纳入集合（挂在停用部门下的用户也应被筛出）。

不改 `sys_dept` 表结构、不改 Controller 契约形状（仍传单个 `deptId`）。

## 5. 验收标准

手工：

1. 用户页搜索出现「归属部门」；清空/重置后不再按部门过滤。
2. 选叶子部门：仅该部门用户。
3. 选有下级的部门：含本部门及所有下级用户，不含其它分支。
4. 带部门条件导出与列表筛选范围一致。
5. 部门管理页与用户表单选部门行为不变。

建议单测：对部门 ID 展开逻辑用固定树断言根/叶子/未知 id 行为。

## 6. 影响面

| 区域 | 影响 |
|------|------|
| 前端用户页 | 搜索增加部门条件 |
| 用户分页/导出 | `deptId` 语义从精确变为含下级（破坏性语义变更，但与产品预期一致；此前搜索未暴露该字段） |
| 部门模块 | 无 |
| 库表 / 权限 | 无 |
