# 部门管理（系统管理）设计说明

**日期**：2026-05-08  
**状态**：已定稿（经 brainstorming 澄清与补充确认：**list 采用方案二（嵌套树）**、**迁移仅 `sys_dept`**、**删除用户占用校验延后至用户表就绪**）  
**依据**：`原始需求/系统管理/部门管理-原始需求.md`、既有 `quick-ui/src/api/system/dept.js`

---

## 1. 背景与目标

- **背景**：原始需求要求树形展示、字段与筛选、增删改查；前端已存在与若依风格接近的部门 API 封装；后端当前以占位迁移与认证为主，**尚无部门实体与接口**。
- **目标**：交付**可联调闭环**：Flyway 建 **`sys_dept`**、后端 CRUD + 树形列表/下拉树、前端部门管理页；删除规则：**存在子部门则禁止**；状态与字典 **`sys_normal_disable`（0 正常 / 1 停用）** 一致；负责人为**文本**。
- **非目标（本迭代）**：在删除接口中校验「部门下是否仍有用户」——**延后**至 **`sys_user`（或等价表）含 `dept_id` 且迁移就绪** 后，在同一删除流程中增加计数校验（见 §7）。

---

## 2. 澄清结论汇总

| 项 | 结论 |
|----|------|
| 交付边界 | 前后端打通的最小可演示闭环 |
| API 路径 | 与 `dept.js` 一致：`/system/dept/list`、`treeselect`、`GET/POST/PUT/DELETE` |
| 列表形态 | **`GET /system/dept/list` 返回嵌套树**（根节点数组，节点含 `children`）；**不**依赖前端 `handleTree` 从扁平转树 |
| 删除（子部门） | 存在子部门 → **禁止删除**，明确错误提示 |
| 删除（用户） | **本迭代不实现**；用户表就绪后补齐（§7） |
| 负责人 | 字符串 |
| 状态 | 与系统用户一致的字典取值 |

## 3. 数据模型（`sys_dept`）

| 字段 | 说明 |
|------|------|
| `dept_id` | 主键，自增或雪花（与项目 ID 策略一致） |
| `parent_id` | 上级部门 ID；**顶级为 `-1`**（与原始需求一致） |
| `dept_name` | 部门名称 |
| `order_num` | 显示排序（同级） |
| `leader` | 负责人（文本） |
| `phone` | 联系电话 |
| `email` | 邮箱 |
| `status` | 与 **`sys_normal_disable`** 一致（建议 `char(1)`：`0`/`1`） |
| `remark` | 备注 |
| `del_flag` | 逻辑删除标记（与项目惯例对齐；若首版无统一惯例则采用 `0` 存在 `2` 删除） |
| 审计字段 | `create_by`、`create_time`、`update_by`、`update_time`（与 quickboot-web 后续模块对齐） |

**索引建议**：`parent_id`、`del_flag` 组合查询；必要时 `dept_name` 前缀索引视数据量再定。

**说明**：不在本迁移中创建 **`sys_user`**；删除接口**仅**校验子部门。

## 4. API 契约（对齐 `dept.js`，载荷形状与 `R.data` 一致）

统一响应：`code` / `msg` / `data`（见 `io.github.genkidoudou.common.api.R`）。前端 `request` 拦截器 resolve 为**整段** `res.data`，业务页取 **`data` 字段**作为载荷。

### 4.1 `GET /system/dept/list`

- **Query**（与需求一致，名称与前端表单字段对齐即可）：`deptName`、`leader`、`status`（均可选）；无附加参数时表示「无筛选」。
- **成功 `data`**：**`List<DeptNode>`**，仅**根节点**出现在顶层数组；每个节点：

  - 业务字段与表一致（含 `deptId`、`parentId`、`deptName`、`orderNum`、`leader`、`phone`、`email`、`status`、`remark` 等）；
  - **`children`**：`List<DeptNode>`，无子则为**空数组**或 **`null`**（实现阶段二选一并在本文档与前端约定一致，**推荐空数组**便于表格）。

**筛选 + 树形（方案二）语义（须实现一致）**：

- **无筛选条件**：返回完整部门树（所有未删除节点，根 `parent_id = -1`）。
- **有任一筛选条件**：返回**剪枝后的森林**——仅包含「自身或子孙匹配筛选条件的节点」，且对每个命中节点**保留从根到该节点的祖先链**，以便树上仍可见路径；不匹配且不在任何命中路径上的分支**不出现**。  
  - 若整棵树无匹配：`data` 为**空数组**。

> **与若依差异说明**：常见若依 `list` 为扁平行；本设计为**嵌套树**，部门管理页**直接** `:data="data"` 绑定 `el-table` 的 `tree-props`，**不再**假定 `rows` 扁平。其它若仍消费扁平 `list` 的代码（若有）需在实现时改为使用 `treeselect` 或单独接口。

### 4.2 `GET /system/dept/treeselect`

- 用于表单「上级部门」等树选择；**成功 `data`**：树形结构，节点至少含 **`id`**（=`dept_id`）、**`label`**（=`dept_name`）、**`children`**（规则同 4.1）。
- 可带与列表一致的筛选 query；**默认**实现可与 `list` 共用建树逻辑（是否允许筛选由产品决定，**首版建议忽略筛选、始终全量树**，避免下拉树与列表搜索耦合）。

### 4.3 `GET /system/dept/{deptId}`

- **成功 `data`**：单条部门 VO（不必含 `children`，或含直接子节点——实现择一，**推荐扁平单条 + `parentId` 便于编辑回显**）。

### 4.4 `POST /system/dept`

- Body：新增实体（无 `deptId` 或忽略）；`parentId` 允许 `-1` 表示顶级。

### 4.5 `PUT /system/dept`

- Body：含 `deptId` 及可更新字段。

### 4.6 `DELETE /system/dept/{deptId}`

- **校验**：存在 **`del_flag` 正常的子部门** → 返回业务错误（`code != 200`），`msg` 可读。
- **不校验**用户占用（延后，见 §7）。

**写操作共性校验**：

- `parent_id` 指向的父节点须存在且未删除；**不可**指向自身。
- **改父级**：不可导致环（不可将节点挪到其子孙之下）；可用「收集当前节点及其子孙 id 集，父 id 不得落在该集合」实现。
- 字段格式：邮箱、手机可选校验，与项目全局校验方式一致。

## 5. 前端（单页：筛选 + 树表）

- **路由/菜单**：与现有 `system/user` 等页面同构注册；权限标识在实现计划中列清单（如 `system:dept:list` 等）。
- **搜索区**：`deptName`、`leader`、`status`（`useDict('sys_normal_disable')`）。
- **表格**：`el-table` + `row-key="deptId"` + `tree-props="{ children: 'children', hasChildren: 'hasChildren' }"`（若无懒加载可不设 `hasChildren`）；数据源为 **`listDept` 返回的 `data` 根数组**。
- **操作**：新增、修改、删除、查看（只读弹窗或抽屉）；上级部门选择器数据源 **`listTreeDept`**（`treeselect`）。
- **删除**：二次确认后调 `delDept`；展示后端返回的 `msg`。

---

## 6. 错误处理与安全

- 业务失败统一 **`R.error(code, msg)`**；HTTP 状态码与项目全局约定一致（通常为 200 + body `code`）。
- 接口需登录态（Sa-Token）；权限与路由 meta 对齐预留。

---

## 7. 延后项：用户占用删除校验

**触发条件**：库中存在用户表（如 **`sys_user`**），且含 **`dept_id`**（或等价外键），并与部门模块同属一库、可统计。

**行为**：在 `DELETE /system/dept/{id}` 中，在子部门校验**之后**（或之前均可，但顺序不影响结果）增加：  
`count(*) where dept_id = ? and del_flag = 正常` **> 0** 则 **禁止删除** 并返回明确文案。

**本迭代**：不建用户表、不实现该校验；在 Service 层可预留 **`UserDeptGuard`** 接口或 TODO 注释，避免遗忘。
