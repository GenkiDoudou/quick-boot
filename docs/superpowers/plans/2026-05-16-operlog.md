# 操作日志 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 quickboot2 中落地操作日志：宽切面 + 事件 + `IgnoreLogger` 采集写入 `sys_oper_log`（含 `trace_id`），并提供 `/monitor/operlog` 管理端与 quick-ui 页面（列表/详情/删/清空/导出）。

**Architecture:** Controller 方法被 `LoggingAspect` 等价物环绕，在 `finally` 中发布携带 `traceId` 与参数/结果/异常的事件；监听器同步脱敏后写库；管理接口独立模块，`POST` 表达删除/清空，导出带行数上限。

**Tech stack:** Spring Boot 3、MyBatis-Plus、Sa-Token、Flyway、Micrometer MDC + `TraceIds`、现有 `common.desensitization`（或薄封装）、EasyExcel（若项目导出已统一则复用）、Vue 3 + Element Plus。

**设计真源：** `docs/superpowers/specs/2026-05-16-operlog-design.md`

---

## 文件结构（预期）

| 区域 | 路径/职责 |
|------|-----------|
| Flyway | `quickboot-web/src/main/resources/db/migration/V15__sys_oper_log.sql`（版本号以仓库当前最大 V 为准顺延） |
| 菜单种子 | 同上文件末尾或 `V16__sys_oper_log_menu.sql`（`menu_id` 与 `logininfor` 等错开） |
| 切面/注解/事件 | `quickboot-common` 或 `quickboot-web` 下独立包，如 `...common.monitor.operlog`（与自动配置同模块，避免 web 依赖环） |
| 监控业务 | `quickboot-web/.../monitor/operlog/` Controller、Service、Mapper、Entity、Bo、Vo |
| 前端 | `quick-ui/src/api/monitor/operlog.ts`、`views/monitor/operlog/`、路由与权限常量 |

实现前通读：`openspec/project.md`、`sdd/后端代码规范.md`、`sdd/前端代码规范.md`、`sdd/数据库设计规范.md`、`DESIGN.md`（前端）。
